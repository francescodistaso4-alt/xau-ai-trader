# XAU AI Trader — V1.0

## Cosa è stato completato
- Motore deterministico ICT/SMC: swing, market structure, BOS, CHoCH, liquidity sweep, FVG, order block, premium/discount.
- Generazione signal-only di Entry, SL, TP1, TP2, TP3 e R:R.
- Filtro multi-timeframe pronto per H4/H1/M15/M5.
- Backtest senza look-ahead: il setup viene calcolato usando solo barre disponibili fino al punto di ingresso; se SL e TP sono nello stesso candle, SL viene contato per primo.
- Diario persistente giornaliero e totale mensile.
- Selezione screenshot/foto del grafico.
- Feed WebSocket e storico HTTP dal backend.
- Grafico prezzo nell'app.
- Notifiche locali BUY/SELL.
- Monitoraggio foreground 24/7 opzionale: continua a ricevere il feed e genera notifiche anche quando l'interfaccia non è aperta, finché Android mantiene attivo il servizio.
- Nessuna API di broker, nessun pulsante di apertura ordine, nessuna funzione di trading automatico.

## Dati reali
Il backend accetta un provider XAUUSD tramite un adapter normalizzato M1. Il provider deve fornire legalmente storico e realtime. Non viene fatto scraping di TradingView.

TradingView Advanced Charts richiede un Datafeed esterno/proprio per i dati; il protocollo del progetto è compatibile con getBars/subscribeBars a livello architetturale.

## Produzione
1. Compilare il backend su un server HTTPS/WSS.
2. Configurare `UPSTREAM_WS_URL`, `UPSTREAM_API_KEY`, `UPSTREAM_SYMBOL` in `.env` con un feed autorizzato.
3. Impostare nell'app l'URL HTTPS/WSS del backend invece dei default emulatori `10.0.2.2`.
4. Per notifiche cloud quando il servizio Android non può rimanere attivo, aggiungere Firebase Cloud Messaging e le credenziali del progetto Firebase; l'app V1.0 usa già notifiche Android locali e monitoraggio foreground per evitare una dipendenza obbligatoria da un progetto Firebase.
5. Aggiungere un provider AI vision al backend prima di usare l'analisi automatica degli screenshot. Senza provider configurato, l'app non deve inventare un'analisi.
6. Testare il motore su dati storici con spread, slippage e sessioni reali del provider.
7. Prima del rilascio, firmare l'APK con una keystore di produzione.

## Sicurezza
- API key del provider solo sul backend, mai nell'APK.
- HTTPS/WSS in produzione.
- Autenticazione dell'endpoint WebSocket consigliata.
- Rate limiting e logging sul backend.
- Nessuna credenziale broker nel progetto Android.

## Nota finanziaria
I segnali sono output analitici e non garantiscono risultati. Il backtest non è una previsione del futuro e deve includere costi, spread, slippage e qualità dei dati.
